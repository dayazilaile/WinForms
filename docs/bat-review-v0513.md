2026-11-19 审查用户提供的 `桌面自动化_SendInput.bat`，仅作为文本读取，未运行样本或其解码脚本。样本 27,532 字节，SHA-256：

`211b6fea1da6ff7d0c7706936d6653f0feefe64eb9a92960fff1f8067d398fd9`

解码得到单次鼠标移动到 (1887,25)，启动延时 3 秒；管理员、诊断、末尾自删除开启，隐藏关闭，没有随机等待。用 v0.5.12 原始生成器重建，同一配置的完整 BAT 在归一化 CRLF/LF 后与样本一致，包括工作流和提权启动段。审查未发现超出这些功能的下载地址、未知植入、持久化或关闭防护的内容。工具本身还有用户明确添加的文件删除/格式化动作，不能把整个自动化工具称为无副作用。

此前核对 v0.5.11-BAT 与 v0.5.12：三个普通流程 × 32 种设置生成的 96 对 BAT 完全相同；增加随机动作的两个样本解码也与生成源码一致。v0.5.12 发布 EXE 源码重建哈希一致。现有证据不支持将此告警单独归因于随机等待或独立提取污染。

## 告警能说明什么

截图显示火绒将文件归为 `TrojanDropper/Agent.ea`，病毒 ID 为 `FC751BE9C80AF10C`，经 cmd 执行时由文件实时监控处理。同一 ID 可以代表同一检测类别或特征，但不能据此确定某一条规则；执行时触发也不代表一定只做了行为检测。未经火绒日志分析或厂商确认，不能断言是提权、Base64、动态脚本、隐藏、自删除或某个字符串单独导致。

这些启动行为都可能增加安全产品审查难度，值得简化和提高透明度；“改成明文后一定通过”不成立。AES 加密、变量/字符串混淆不能提供可信的兼容性结论，也不作为本次修改方向。

## 本次改动边界

1. 自动 UAC 和隐藏运行的启动段用固定 ASCII 明文命令替代 EncodedCommand，路径用环境变量传递；保留标准 RunAs、管理员检测、取消/失败停止及全部设置。
2. 只有输入或诊断需要时加载输入桥接，只有窗口激活需要时创建 WScript.Shell；现有鼠标/键盘实现、DPI 和文字输入能力保留。
3. 单 BAT 的工作流主体仍是原有 Unicode Base64 内容并动态执行，**未移除自读/解码执行结构**；没有采用加密、混淆、策略绕过、排除项或关闭安全软件。
4. 回归核对两引擎 × 隐藏/管理员/删除/诊断共 32 组，解码主体与各组生成脚本逐字一致；检查导出只产生一个 BAT，启动命令低于 cmd 长度限制。Windows 测试另保存所有启动段用于语法解析，并模拟提权三个分支及含中文、空格、单引号、&、% 的文件路径；模拟不等同于真实 UAC 验收。

## 验证限制与实机记录

本次云端完成源码编译、类型引用、功能/UI 模拟和上述静态核对；没有 Windows 运行环境和火绒引擎。ClamAV 病毒库下载不可达，**没有完成有效杀毒扫描**。不能将测试通过写成“无毒”“免杀”或“已解决拦截”。

在火绒保持开启的自有测试机上，由更新后的程序重新生成只含等待或鼠标移动的测试 BAT，按实际需要验证现有选项；记录火绒/病毒库版本、BAT 哈希、导出设置及详细日志。若仍报同类告警，应把最小可复现文件与源码交给火绒官方误报渠道核实。不要将生产环境关闭防护当作验收方法。
