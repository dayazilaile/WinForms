# V0.5.17 主程序告警审查与 V0.5.18 整理记录

## 告警范围

2026-11-22 用户反馈，双击 `ITDesktopToolkit.exe` 时火绒将其归为 `HEUR:Trojan/MSIL.AutoRun`；截图路径为 v0.5.17 包内的 build 主程序。本次不是之前生成 BAT 的 TrojanDropper/Agent.ea 记录。

HEUR 表示启发式检测，MSIL 对应 .NET 托管代码分类；名称里的 AutoRun **不能单独证明程序写了开机启动**，也不能证明误报。执行时由文件监控处理，与文件加载/访问扫描相符，但不能仅凭截图确定触发规则或拦截前执行到了哪一条指令。

目前没有取得用户电脑上被检测的 EXE 样本，因此未完成该文件的二进制核对。

## 已取得的证据

1. 对 v0.5.16 与 v0.5.17 标签作源码差异检查。Program.cs 未改变；MainForm 的启动/概览流程仅版本文字变化。新增批量清理入口是菜单 → 模式窗口 → 明确生成 BAT；没有新增启动即卸载、开机自启动登记、后台下载或远程执行步骤。
2. 使用相同的 Mono/C# 5 编译器与微软 .NET Framework 4.8 引用程序集分别重建两个标签，再通过仅反射读取的 CIL 检查器审查入口，没有执行重建 EXE 的 Main 方法。两版 Program.Main 入口指令完全一致：启用界面样式、设置文本渲染、创建 MainForm、进入 WinForms 消息循环。构造器扣除版本信息和新增空导出委托字段后相同。
3. v0.5.17 的 SoftwareCleanupScriptService 没有类型初始化器，旧清理内核为字符串常量，不会因载入类型自动执行；只有用户明确导出，再在目标机运行生成 BAT 才调用清理逻辑。该逻辑包含正常管理员阶段和卸载器调用，确实值得安全产品审查，但尚未确认它是这条告警的具体触发点。
4. 从标签重建的云端 v0.5.17 EXE 与当前云端保留的旧产物逐字节一致。SHA-256：

   `46f70327b61c6e9caa65aebd6a8efdd4a9168f9e8d90b2b3b09b524493e7a17f`

   此哈希仅代表**云端 Mono 产物**，不代表用户在 Windows 用 csc 编译的文件。不同编译器和构建元数据会造成哈希不同，不能据此单独认定文件被感染。
5. v0.5.18 将清理内核作为可直接审阅的 `Scripts/SoftwareCleanup.ps1` 文件随工具箱部署，生成前校验规范化内容 SHA-256；缺失、被改动、超大或版本不符时停止生成。程序启动不读取或执行它。模板是函数定义，具体标准与调用由用户导出时写入 BAT。
6. 用户要求与现有 BAT 自动化保持相同写法。两者现在直接共用 `BatScriptPackage` 的 BAT 头、可见 PowerShell 启动、路径变量、载荷标记、Unicode 编码与写入流程；没有改写自动化输入或清理业务策略。清理模板与原版相比只将自身路径变量改为共用的 IT_TOOLKIT_BAT。学生机仍只需要一个 BAT，不依赖模板文件。
7. 以三个原有流程 × 两引擎 × 隐藏/管理员/删除/诊断共 96 组配置生成 BAT，重构后的完整文件全部与 v0.5.17 逐字节一致。软件清理另验证共享启动行、模板校验和模拟运行；全部测试不执行真实卸载、实际 UAC 或未知样本。

## 验证的边界

云端没有火绒引擎或 Windows。ClamAV 官方病毒库下载仍被网络端点拒绝，未完成有效病毒库扫描；功能/UI 测试不能代替杀毒检测。没有证据支持将用户文件直接宣判为病毒或误报，也不能说 V0.5.18 已保证不再提示。

本次修改提高代码共享和可审查性，不通过混淆、加密、改名或关闭防护处理。完整保留现有单 BAT、管理员、鼠标键盘、条件/重试、隐藏、自删除和清理模式；隐藏模式仍由用户明确选择，清理脚本使用可见启动。

应保持火绒开启，用完整 V0.5.18 包重新编译复测。如果仍提示，需要该次被检测文件/文件 SHA-256、火绒与病毒库版本及详细检测记录进一步核对，必要时交火绒官方复核。未收到样本前，无法排除本机编译环境或产物与仓库不同的情况。

可核对的摘要见 [security-review-v0518.json](security-review-v0518.json)。
