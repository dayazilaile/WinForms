# 跨机房唤醒（v0.6.5 待试用）

入口：**新增 · 待试用 → 跨机房唤醒**。功能是试发 WOL 魔术包，不需要修改网络配置；是否送达仍由现有网络、待机供电及网卡/BIOS支持决定。

## 怎么用

1. 保留原软件目录中的 Data/students-v055.tsv。页面读取同一份机房/IP/MAC记录；修改或导入请点“管理原机房清单”。升级时把自己的整个 Data/Logs 复制到新 EXE 旁。
2. 选择实际通向机房的本机 IPv4 网卡、一个具体目标机房。目标机需要已保存的有效私有 IP 和有线网卡 MAC。不同机房不在同一批次发送。
3. 目标掩码填位数：每个机房为192.168.xxx.1–254、掩码255.255.255.0时填24。其他实际掩码按位数填写，试用范围16–30。这里只用于计算和校验，不更改任何机器配置。
4. 默认先用“单播”，选一台机器点“尝试唤醒选中”，确认 IP/MAC 和发包目的地址，再查看实际学生机。
5. 单播无效时，可手动选广播或“组合尝试”。“尝试唤醒该机房”包含当前具体机房的全部已保存记录。
6. 结果和双击详情展示路径、目的地址、包数和失败原因。只有“交给系统”，没有送达回执；学生机是否开机必须另外观察。不会先要求目标能Ping通，也不以Ping回复冒充已经唤醒。

## 四种方式

| 方式 | 发送到哪里 | 可能有效的条件 |
| --- | --- | --- |
| 单播（先试） | 保存的目标IP，UDP9 | 已有路由可达、目标网关能解析学生机MAC、网卡接受单播WOL |
| 目标网段广播 | 按目标IP及实际掩码计算的广播地址，UDP9 | 网络设备现有配置已允许定向广播转发；工具不配置它 |
| 本地广播 | 所选本机接口的广播地址，UDP9 | 两个机房实际处于同一广播域；三层路由通常不会转发 |
| 组合尝试 | 依次尝试以上三种；相同地址去重 | 便于一次比较发送路径；依然不能保证开机 |

每个目标、每条路径最多3包，每包102字节，使用该目标保存的MAC。路由尝试TTL16，本地广播TTL1。不遍历其他网段、不扫描端口、不改ARP缓存、不安装代理、不发关机请求、不更改交换机/路由/电脑IP/防火墙。

跨网段不能通过本机ARP直接核对远端机器的MAC；记录过期会把单播包发到旧IP，通常也不能唤醒预期机器。确认窗口仅展示保存记录，不代表实时身份验证。默认仅私有IPv4，拒绝本机（含其他网卡IP）、特殊/公网/缺失IP、子网号、广播地址及重复IP/MAC。全部目标先预检，无效一项就不发送整批。

## 能Ping通为什么还可能唤不醒

开机时能Ping通是正常IP通路的证据。关机后网络栈不再正常工作，网卡有待机供电也不保证会回答ARP。目标网关保存的ARP缓存可能随后过期，单播唤醒包会停在网关；目标广播则常被现有配置丢弃。

推荐先在学生机开机时核对IP/MAC和WOL设置，再正常关机，分别**马上、十几分钟后**各试一次。不要只凭刚关机成功就认定长期可靠。若只在短时间有效，可能与邻居缓存有关；具体原因仍需机房实测，软件无法绕过现有网络的限制。

如果所有方式均无效，而不能改交换机配置、目标机房又没有可代发的在线设备，那么当前条件下可能无法可靠跨网段唤醒。本版不会伪装成功。

## 数据、记录和停止

清单格式与原路径不变。工具审计日志位于 **EXE目录/Logs/operations-v1.tsv**，包含本机身份/时间/版本及目标机房、名称、IP/MAC、方式、掩码、目的地址和发包结果。软件日志不可写不会回退到AppData/TEMP，界面仍可查看本次结果。

停止或切页只停止后续包，已发出的无法撤回。界面保留部分包数与停止状态；切页后本次详情不常驻保存，查看审计日志。软件没有中继服务，本次未改变同网段唤醒或远程关机实现。
