# V0.5.20 清理功能告警复核

用户明确反馈：加入机房软件清单对照/批量卸载功能后，双击主程序即被拦截；360 提示“创建进程”。用户尚未测试 v0.5.19。旧记录见 security-review-v0518.md，本次不将旧版或新版写为已解决告警。

## 审查证据与修改

1. 复核 v0.5.16（清单对照）与 v0.5.17（批量清理）及当前版本。此前记录已核对 v16/v17 的 Program.Main 相同，MainForm 构造启动没有增加清理调用；当前新入口仅增加运行库与软件目录检查。清单页面只读注册表/已保存标准；卸载必须经入口和确认，导出清理模板只在明确生成时读取。没有新增自动开机启动、后台下载、远程载荷、进程注入或启动即清理路径。
2. 托管代码共三类进程入口：CommandService 的管理命令/手工管理工具/UAC 重启；NetworkConfigService 的手工 netsh；SoftwareUninstallService 的明确卸载。均接入进程启动观测点。UI 测试等待概览与数据库完成，验证未请求创建子进程。WMI 服务可能自行启动提供程序，本测试不能保证 Windows 全系统没有新进程。
3. 管理命令固定到 Windows 系统目录，避免当前目录/PATH 同名程序替换；管理 PowerShell 以可审阅的直接 -Command 传参，保留中文/引号测试，不采用 EncodedCommand、策略绕过或混淆。命令长度超限停止，不切换到隐藏释放器。正常管理行为仍会创建进程，不能承诺安全产品无提示。
4. 单项卸载额外拒绝 cmd/PowerShell/WSH/mshta/rundll32/regsvr32 等通用执行器、无法核对产品 GUID 的 MSI 和直接 UNC 运行。普通厂商卸载器与有效 MSI 产品代码保留。批量清理仍按标准逐项核对、保护安全/教学/驱动/运行库项目，不强杀安装器或主动重启，仅弹窗反馈。Scripts/SoftwareCleanup.ps1 继续以规范化 SHA-256 校验，未改业务模板。
5. 工具箱仍保留用户明确操作的系统维护功能，例如既有 Defender/防火墙临时控制、启动项管理、UAC、输入模拟与网络设置。这些是安全产品可合理提示的敏感行为，不因本次排查而用于关闭 360/火绒或掩盖操作；它们不在启动路径执行。敏感功能存在不等于病毒，同时源码审查也不能证明二进制无毒。
6. 自动日志/配置/恢复备份改为 EXE 旁的 Logs/Data，BAT 的网络备份改为 BAT 旁 Logs；没有电脑用户目录/TEMP 兜底。旧文件不自动迁移/删除。删除便携目录不清除系统或第三方日志，也不撤销系统修改。
7. 添加 Win7/Server 的明确组件要求与兼容路径。旧系统缺失 NetTCPIP 的写操作提前拒绝，保留 netsh/WMI 手工 IPv4；没有假造兼容成功。Server 包冻结，未来不自动把普通版修改写入定版。

## 结论边界

未发现所审源码含新增的自动恶意执行路径；**没有取得用户本次被拦截 EXE 的样本/哈希及完整父子进程记录，没有 360/火绒引擎或有效病毒库扫描，也没有真实 Windows/Server 测试。** 不能排除发布文件与仓库不同、用户编译环境差异或安全产品仍按敏感功能告警，不能称为“无毒证明”或保证误报消失。

应在防护保持开启的情况下，对照同版本完整包和自己编译的 EXE，记录具体文件 SHA-256、父/子进程路径、命令行、360/火绒版本及处置详情，再进一步归因。无需添加白名单或关闭防护。本次更改着重消除路径劫持和不受控卸载入口，不能据此反推该问题就是这些入口造成的。
