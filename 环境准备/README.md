# WinForms 环境准备

这个文件夹可以整体复制到 U 盘，也可以单独带到其他电脑使用。不改工具箱功能、版本号或 Server 定版代码。

## 怎么使用

1. 双击 **01_检测环境.bat**，先查看系统、位数、.NET、Windows PowerShell 和待重启状态。只检测，不安装、不写日志。
2. 根据 [安装包说明](安装包/README.md)，从微软官网下载缺少的安装包，放进本文件夹的 **安装包** 子目录。
3. 右键 **02_安装缺少组件.bat**，选 **以管理员身份运行**。它会列出本次要装的组件，输入 `Y` 才安装，每次只装一个。
4. 按提示自行重启，再检测。Win7 通常先装 .NET 4.8，再重新运行安装入口装 WMF 5.1；新组件安装后请新开窗口检测。

脚本不联网下载。已有 .NET 4.8 或更高 4.x、PowerShell 5.1 时跳过对应安装。已装 .NET 4.5～4.7 时升级 4.8 是建议，不代表工具箱主程序无法运行。32/64 位由操作系统架构决定，不由当前 PowerShell 进程位数决定。

## 环境要求与范围

| 系统 | 使用说明 |
| --- | --- |
| Win7 | **必须 SP1**。主程序最低 .NET 4.5，建议 4.8；自动化 BAT 需 Windows PowerShell 5.1（自身至少需 .NET 4.5.2）。检测/安装入口按系统自带的 PowerShell 2.0 语法编写，无需先有 5.1 才能启动 |
| Win10 / Win11 | 通常已有组件，仍以检测值为准。早期 Win10 或精简系统可能需要系统更新；不会安装 Win7 的 WMF 包 |
| Win8.1 | 支持识别对应 x86/x64 的 WMF 5.1 包 |
| Server | 辅助识别 2008 R2 SP1、2012、2012 R2、2016 及以上 x64 桌面环境的包；此助手不改写 v0.5.20-Server 定版。安装 WMF 前须核对管理产品兼容性；不处理无桌面/缺少 WMI、PowerShell 的精简系统 |

安装环境不能补出旧系统没有的网络模块，也不能保证所有工具功能在不同 Server 角色上都可用。只运行别人已编译好的程序，不需要安装 Visual Studio；自行编译请使用项目根目录的构建入口。

## 常见提示

- **脚本被执行策略阻止**：本助手不修改执行策略、不加 Bypass、不隐藏窗口。请让机房管理员按现有策略审批、签名或授权此脚本。Win7 默认策略可能阻止 PS1，这种情况下可按上面的官方说明手动安装；.NET 还可用项目根目录的 Check_Runtime.bat 只读核对。
- **已有待重启操作**：先自行重启，不继续叠加安装。安装入口不会强制重启。
- **签名验证失败或安装失败**：停止操作，核对官方来源、时间、证书、系统更新及包的适用性；错误码会显示。脚本不会尝试关闭杀毒软件或修改更新/安全服务。
- **找不到 Windows PowerShell / WMI 读取失败**：通常是精简/损坏系统或权限限制，需要先由管理员修复系统组件。PowerShell 7 不替代 Windows PowerShell 5.1。
- **无法写入日志目录**：安装不会开始。把整个文件夹放到有写权限的位置，或解除 U 盘写保护，不会转存到用户目录。

安装操作日志保存在本文件夹 **Logs/environment-install.tsv**，包括时间与时区、主机名、MAC、IP、系统、账户、组件和安装器退出码；.NET 详细安装日志也指定在 Logs 中。检测不创建日志。微软安装器和 Windows 自身仍可能在系统中写入缓存、事件和安装日志，删除这个文件夹不等于卸载组件或清除系统安装记录。

退出码：`0` 检测达标/安装器成功/用户取消；`5` 检测到环境不足或未识别支持范围；`1` 错误或安装被阻止；`3010` 安装器要求重启。检测成功仅表示达到主程序最低 .NET 与自动化 PowerShell 要求，建议升级项和待重启信息仍以屏幕提示为准。

安装包不包含在源码中。已在云环境核对逻辑与模拟安装场景，未在真实 Win7/Server 安装或杀软环境中验收。
